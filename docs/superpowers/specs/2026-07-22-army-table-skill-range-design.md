# ArmyTable 技能字段与远程攻击范围调整设计

## 目标

1. ArmyTable 的 `SkillIds` 字段不再由关卡工具处理：导入时忽略，同步时不写入，保留工作簿中的原值。
2. 弓箭手（角色 1）和法师（角色 4）的攻击范围增加一倍。
3. 攻击范围调整必须是幂等的一次性迁移，避免重复加载和同步后从两倍继续增长为四倍或八倍。

## 实现设计

### SkillIds

- 删除 ArmyTable 导入流程中从 `SkillIds`、`CommonSkill` 或 `UnlockSkillOrigin` 推导 `commonSkill` 的逻辑。
- 导入单位不再因 ArmyTable 技能字段设置 `commonSkill`。
- 从 `syncArmyTable` 的字段映射中删除 `SkillIds`，同步已有行时保留原单元格，新行沿用模板/同步工具的既有未映射字段行为。

### 攻击范围

- 将默认职能权重中的弓箭手攻击范围从 600 改为 1200，法师从 500 改为 1000，使新生成单位直接采用翻倍后的范围。
- 对当前项目内 `public/ArmyTable.xlsx` 执行一次性数据迁移：依据 `Roles` 判断角色，仅将弓箭手和法师行的 `AttackRange` 翻倍。
- 加载流程不再额外乘以二，而是直接读取迁移后的值，因此后续加载和同步不会重复放大。
- 不调整侦测范围 `detRange`，也不调整其他职业。

## 数据流

新生成单位从更新后的默认职能权重获得攻击范围。已有单位从完成一次性迁移的 ArmyTable 读取攻击范围。同步时写入单位当前攻击范围，但不处理 `SkillIds`。

## 验证

- 单元测试证明 `syncArmyTable` 不覆盖现有 `SkillIds`。
- 单元测试或配置断言证明弓箭手/法师默认攻击范围分别为 1200/1000。
- 检查迁移前后 ArmyTable，仅角色 1 和 4 的 `AttackRange` 精确翻倍；其他角色保持不变。
- 连续加载/同步验证攻击范围不会再次翻倍。
- 运行相关测试套件，确认既有 ArmyTable 同步及单位生成行为无回归。

## 非目标

- 不修改技能编辑 UI 或其他非 ArmyTable 技能系统。
- 不改变生命、攻击、攻速、侦测范围或其他职业参数。
- 不修改用户当前未提交的 `.env` 文件。
